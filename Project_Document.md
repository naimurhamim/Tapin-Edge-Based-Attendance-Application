## 1. Project Overview

**Project Title:** TapIn — Smart Attendance System
**Version:** 2.0.0
**Platform:** Android Mobile Application (Flutter)
**Backend:** Supabase (Cloud PostgreSQL + Authentication + Edge Functions)
**Hardware:** NodeMCU ESP8266 + RC522 RFID Reader Module

TapIn is an IoT-integrated smart attendance management system designed for university use. The system features three main panels: **Admin**, **Teacher**, and **Student**. A student can tap their RFID card on a NodeMCU device installed in the classroom, or scan a dynamic QR code generated by the teacher's app. The device or app sends the unique identifier to a Supabase Edge Function over HTTPS, and the system automatically records the attendance in a cloud database. Teachers can also take manual attendance, view analytics, and export reports to PDF and Excel. Students and admins view this data in real time through this Flutter mobile app. Geofencing ensures that attendance via QR is only accepted if the student is within the classroom boundary.

## 4. Hardware — NodeMCU and RFID System

### 4.1 Hardware Components
- NodeMCU ESP8266 (WiFi-enabled microcontroller)
- RC522 (MFRC522) RFID Reader
- Standard ISO 14443A RFID Cards

### 4.2 NodeMCU Code Flow
- Connects to WiFi (`naim` network).
- Initializes SPI and RC522 module.
- Polls for new RFID cards.
- When a card is detected, reads the UID, converts it to HEX, and sends an HTTP POST request to the Supabase Edge Function (`mark-attendance`).
- Receives JSON response containing success status, student name, tap time, and course name, and outputs it to the Serial Monitor.
- Has a 3-second cooldown to prevent double-scanning.

## 5. Supabase Backend

### 5.1 Database Schema

**1. users:** Stores profiles for students, admins, and teachers.
**2. subjects:** Academic subjects/courses.
**3. class_schedules:** Weekly class timetable.
**4. attendance_logs:** Core attendance records.
**5. leave_applications:** Student leave requests.
**6. teacher_courses:** Maps teachers to the subjects they teach.

### 5.2 Edge Functions
The system uses a Supabase Edge Function (`mark-attendance`) to handle RFID taps. It securely looks up the student by `rfid_uid`, checks the active `class_schedules`, and inserts a record into `attendance_logs`.

## 6. Business Rules

1. **Lab Group Assignment:** Based on last 3 digits of university ID. Digits <= 25 assign G1, digits > 25 assign G2.
2. **Attendance Threshold:** Minimum 90% attendance is required.
3. **RFID Linking:** Admin MUST assign an RFID card UID to a student profile before that student's card taps are recognized by the IoT device.
4. **Condoned Status:** When admin approves a leave application, the corresponding attendance is updated to 'condoned'.
5. **Geofencing:** For QR code attendance, the student's GPS location must fall within the configured geofence radius around the classroom coordinates.
6. **Cascading Deletes:** Deleting a course or schedule automatically cleans up related attendance logs to prevent database constraint errors.
